# Module 8 assessment mapping

| Requirement | Implementation |
| --- | --- |
| Role cards and assignments | Researcher, Designer and Tester have named assignments, scoped inputs, status and output. |
| Traceable handoffs | Research output reaches Design and Testing independently. Expand either handoff to see what moved and when it was used. |
| Comparison and conflict | Compare the three positions, recommendations, rationale and uncertainties. The UI flags differing positions. |
| Human decision | The server accepts a choice and rationale only after the three role outputs exist. |
| Synthesis | A separate step receives role outputs and the decision. It proposes a next action, owner and open risk. |
| Decision log | The log records the project lead’s exact choice, rationale and timestamp. The JSON export includes the review and handoff paths. |
| When to use multiple roles | The README compares release reviews with routine single-role tasks and discusses added latency and shared model bias. |
